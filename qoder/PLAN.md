# 03：研途 ResearchLoop

## 要解决的问题

论文摘录、会议纪要和行动项分散在不同文件里，查资料时难以找到出处，写周报时又要重新整理任务。研途把资料检索和任务推进放到一个工作台。

## 最小完整项目

1. 导入 Markdown / TXT 学习或研究资料，保留文件名和分块出处。
2. 使用 seekdb 或 PowerContext 实际保存、检索内容。用户可以用一句话查询资料并回看原文，不生成无出处的研究结论。
3. 从资料手动创建行动项，设置负责人、截止日期、状态和关联出处。
4. 按本周完成、待解决问题、下周计划整理可复制的周报；自动整理属于模板规则，只有接入真实模型时才称为 AI 生成。
5. 提供公开可访问的项目介绍、使用说明、演示数据入口和架构说明，通过 Qoder Sites 发布。后台服务暂不可用时给出明确状态，不把示例结果冒充数据库返回。

## 关键技术决定

- 03 的主体代码必须由 Qoder 开发，保存真实的开发对话、运行截图或录屏。当前目录中的方案和提示词仅为开发准备，不能算作 Qoder 开发记录。
- 推荐 React / TypeScript 前端及 seekdb-js 服务端；先让 Qoder 核查 Qoder Sites 当前可用的 Function / 数据库能力，再决定部署架构。Sites 托管环境无法访问用户电脑上的 127.0.0.1，不能把本机 API 地址用于公开站点。
- 若复用 stepfun 的分块或检索方案，应在 README 标注复用来源。03 的任务与周报功能需由 Qoder 实际实现，两个题目分别说明、分别提交。
- 不在前端、Git 或截图中暴露数据库密码、访问令牌、模型 API Key。

## 验收演示

导入一份含“实验复现”和“论文阅读”的资料 → 搜索“怎样保证实验可以复现” → 打开原文出处 → 新建“补齐实验依赖版本”任务并设置截止日 → 完成任务 → 周报出现该任务与出处。重新打开页面，验证真实持久化及集合隔离。最后用无登录浏览器验证公开的 Qoder Sites URL。
