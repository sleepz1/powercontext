# 对照题面

题面摘录见 `YUQUE-Dify.md`。下面只列本作品怎么对上验收，不预估分数。

## 基础验收

| 条件 | 本仓库里的材料 | 评审还要在自己的环境里做 |
| --- | --- | --- |
| 能够运行 | Chatflow DSL、依赖版本、环境变量增量、牌库文件 | 按 `README.md` 启动 Dify 与 seekdb，导入 DSL，重绑知识库和模型 |
| 能够体验主要功能 | `scripts/smoke.md` 的主题抽卡、再来一张、对不上牌库 | 用新会话按样例各走一次 |
| 技术结合有效 | seekdb 只做向量库；Chatflow 的「牌库检索」消费召回；卡面原文来自片段 | 索引完成后执行样例 D 的 SQL，看到 `text` 列里的 `card_id` |
| 过程可以复现 | 16 张牌、分段方式、占位符、重置会话的方法都写在运行说明里 | 不依赖作者本机已有的库或 Key |

开放式输出不设唯一标准答案。线上「再来一张」只要换成召回结果里的另一张同主题牌即可。本地脚本因为看得见全牌库，样例 B 固定为 `OB-002`。

## 作品评价所对应的设计

| 维度 | 设计 |
| --- | --- |
| 创意 | 用文字梗图包住一条可核对的冷知识，稀有度只决定抽哪一层 |
| 趣味与互动 | 主题、稀有度、「再来一张」、对不上就拒答。吐槽和事实分开 |
| 体验 | 开场白、四个建议问题、固定卡面。没摸到时不调用模型 |
| 技术结合 | Dify 负责编排和会话内记忆，seekdb 负责牌的向量和原文 |
| 可复现 | 一文件一牌；DSL 由 `cardlib.py` 生成；`check_deck.py` 执行 DSL 中的代码 |

评分细则、权重和评测资源限制以赛事后续公布为准。
